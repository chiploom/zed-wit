# Zed WIT extension 0.5.1

This release prepares Chiploom's first published WIT extension for Zed, succeeding the original implementation with permission from its maintainer, Valentine.

The extension provides modern WebAssembly Interface Types (WIT) support through syntax-aware editing and a native language server for diagnostics, formatting, completion, navigation, and code actions.

Version `0.5.1` supersedes the unpublished `0.5.0` release candidate. The earlier publication attempt was stopped by a fail-closed GitHub Actions tag-protection check before a release tag or GitHub Release was created.

## Highlights

### Modern WIT language support

- Syntax highlighting using the pinned Bytecode Alliance Tree-sitter WIT grammar.
- Support for packages, interfaces, worlds, resources, types, functions, and annotations.
- Recognition of modern WIT grammar constructs, including async functions, futures, streams, maps, and nested packages.
- Automatic `.wit` file recognition and WIT Markdown code-fence support.
- Bracket matching, automatic indentation, code outlines, and Vim text objects.
- Snippets for packages, interfaces, worlds, types, functions, imports, exports, and `use` declarations.

### Native WIT language server

- Native language server built on upstream `wit-parser` semantics.
- Parser-backed syntax, name-resolution, and type diagnostics.
- Scope-aware completion, including local types and imported declarations.
- Hover information, go to definition, and find references.
- Safe quick fixes for unresolved types when suitable candidates exist in scope.
- Multi-file package analysis, including sibling files and supported local `deps/` layouts.
- Unsaved-buffer support for package files and dependencies.
- Incremental document synchronization and diagnostics updates.

### Document formatting

- Topiary-based document formatting.
- Comment and documentation preservation.
- Consistent, idempotent formatting.
- Configurable spaces and tabs.
- Refusal to format syntax-invalid documents rather than risk producing incorrect output.

### Native server distribution

- Uses the published, immutable WIT Language Server `v0.1.2`.
- Automatically downloads the appropriate native executable when no configured server is available.
- Verifies executable integrity using SHA-256 checksum sidecars.
- Caches verified downloads to avoid unnecessary network requests.
- Detects corrupted executable caches and missing checksums, then recovers automatically.

Supported native server targets:

| Platform  | Architecture  |
| --------- | ------------- |
| macOS     | ARM64, x86_64 |
| Linux GNU | ARM64, x86_64 |
| Windows   | x86_64        |

The extension and native language server maintain independent release versions. The extension remains explicitly pinned to LSP `v0.1.2`.

## Release infrastructure and reliability

This release also incorporates improvements to the project's publishing infrastructure:

- Version-aware Rust `xtask` commands for release planning, preparation, validation, and protected publication.
- Separate release streams for the native language server and Zed extension.
- Human-reviewed release preparation through protected pull requests.
- Verification of the exact reviewed release source commit.
- Audited tag-protection ruleset validation that handles GitHub's permission-dependent API responses without weakening protection.
- Fail-closed behavior when the audited tag ruleset changes or required protections are missing.
- Bounded reconciliation of temporarily incomplete GitHub Actions run metadata after a confirmed CD dispatch.
- Immediate rejection of explicitly mismatched workflow run IDs or source commits.
- Protected publication requiring validated release metadata and immutable-release enforcement.

No additional administration-write credential is required by these changes.

## Validation

The implementation has previously completed:

- 174 passing workspace tests during the `0.5.0` release preparation.
- Formatting, Clippy, Cargo dependency checks, and WebAssembly adapter builds.
- Hosted Zed integration testing on macOS ARM64 covering initial download, verified cache reuse, corrupted executable recovery, and missing checksum recovery.
- Real-Zed GUI qualification on macOS ARM64 for supported editor functionality.
- All six required GitHub CI checks for the subsequent release-policy fixes in PR #32.

These results document prior qualification. The final `0.5.1` release candidate remains subject to its own required checks and protected CD validation.

Native release assets exist for all five supported targets. Real-Zed hosted runtime qualification on macOS x86_64, Linux ARM64/x86_64, and Windows x86_64 remains tracked separately in issue #22.

## Known limitations

- Package dependency discovery is restricted to supported local file and directory layouts.
- Remote dependency downloads and encoded binary component dependencies are not supported.
- Some newer syntax recognized by the grammar remains gated by upstream WIT semantic support.
- Native binaries outside the five supported target combinations are not distributed.
- This GitHub extension release does not itself publish or update the Zed extension registry.

## Maintenance and acknowledgements
