# Zed WIT extension 0.5.4

This patch release addresses a Rust toolchain compatibility issue that prevented Zed's extension registry from packaging Chiploom's WIT extension.

The extension's WebAssembly adapter now supports Rust 1.90, matching the toolchain used by Zed's extension packaging infrastructure. The change preserves the existing WIT language features, native language-server integration, and runtime dependencies introduced in `0.5.3`.

No user-facing language functionality changes are intended.

## Changes

### Rust 1.90 packaging compatibility

The original `0.5.3` release declared Rust 1.99 as the minimum supported version for the WebAssembly adapter. However, Zed's extension packaging workflow uses Rust 1.90, causing its `package` CI job to reject the extension before compilation.

This release:

- Lowers the root `zed-wit` adapter's minimum supported Rust version from `1.99` to `1.90`.
- Preserves the Rust 2024 edition.
- Retains Rust 1.99 as the project's primary development toolchain.
- Keeps native language-server development and auxiliary tooling independent of the adapter's compatibility requirement.
- Preserves the existing locked dependency versions and WebAssembly build target.

The compatibility change is limited to the adapter's minimum supported Rust version and does not modify its runtime behavior.

### Automated compatibility testing

A dedicated `Zed registry compatibility` GitHub Actions job now independently validates the adapter using Rust 1.90.0.

The job:

- Installs Rust 1.90.0 and the `wasm32-wasip2` target.
- Verifies the active Rust compiler version.
- Runs the adapter's unit tests using locked dependencies.
- Builds the adapter in release mode for `wasm32-wasip2`.
- Fails if the adapter cannot compile under Zed's expected Rust toolchain.

The existing Rust 1.99 workspace checks, native platform tests, and protected release validations remain unchanged.

This provides explicit regression coverage for a compatibility requirement that was previously not exercised by the project's CI.

- Successful Rust 1.90.0 release-mode WebAssembly build on macOS ARM64.
- Successful Rust 1.90.0 adapter unit tests in GitHub Actions on Linux: 6 passed, 0 failed.
- Successful Rust 1.90.0 release-mode WebAssembly build in GitHub Actions on Linux.
- All six required CI checks passed for [PR #40](https://github.com/chiploom/zed-wit/pull/40).

The `0.5.4` release candidate must also pass its own required CI checks and protected CD validation before publication.

The upstream Zed registry's end-to-end packaging check will be revalidated separately after the registry pull request is updated to this release.

## Compatibility and distribution

The extension remains pinned to the published, immutable WIT Language Server `v0.1.2`.

Supported native language-server targets:

| Platform  | Architecture  |
| --------- | ------------- |
| macOS     | ARM64, x86_64 |
| Linux GNU | ARM64, x86_64 |
| Windows   | x86_64        |

There are no changes to:

- The extension ID (`wit`) or its language-server configuration.
- WIT syntax highlighting, snippets, diagnostics, completion, navigation, or formatting.
- The pinned Bytecode Alliance Tree-sitter WIT grammar.
- The native language-server version or supported platform matrix.
- Native executable downloads, SHA-256 integrity verification, or cache recovery.
- The independent extension and native language-server release streams.

This is an extension-only release. No new native language-server binaries are required.

### Zed registry publication

The maintainership transition from [valentinegb/zed-wit](https://github.com/valentinegb/zed-wit) to [chiploom/zed-wit](https://github.com/chiploom/zed-wit) is being coordinated through [zed-industries/extensions#7984](https://github.com/zed-industries/extensions/pull/7984).

Publishing this GitHub release does not automatically update the Zed extension registry. The registry entry must reference the new extension release and pass Zed's packaging validation before the update can be accepted.

## Known limitations

This release does not change the functional limitations documented in [extension 0.5.3](v0.5.3.md).

In particular:

- Package dependency discovery remains limited to supported local file and directory layouts.
- Remote dependency downloads and encoded binary component dependencies are not supported.
- Some newer WIT syntax remains gated by upstream semantic support.
- Native language-server distribution remains limited to the five supported targets.
- Real-Zed hosted runtime qualification on the remaining supported platforms is tracked separately in [issue #22](https://github.com/chiploom/zed-wit/issues/22).
